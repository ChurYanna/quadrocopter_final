SV-STCP 多模态语义验证时空协同通行算法阶段性报告

阶段版本：复杂混合障碍在线 VLM 闭环 Demo 版
报告范围：只讨论算法结构、关键机制、设计取舍与阶段性创新点

1. 算法核心定义

当前算法可概括为：面向多无人机编队在动态窄洞与实体混合障碍区中的安全通行任务，构建“传感器融合结构化上下文（SFSC）+ 前视 RGB + VLM 高层策略 + 确定性安全验证 + 底层稳定执行”的分层闭环框架。

算法不把 VLM 放入底层控制回路，也不让 VLM 直接输出速度、推力或轨迹。VLM 只负责高层路线族和局部 PassagePlan 候选；是否可以执行、何时执行、怎样转换成连续控制，由确定性模块裁决。

一句话算法主线：SFSC 给出几何、队形、时序和安全约束，前视 RGB 给出真实视觉形态证据，VLM 在二者融合基础上提出高层策略候选，候选经安全验证、返回时效性门控和安全投影后，才进入按障碍缓存的底层执行计划。

3. 为什么采用“SFSC + 前视 RGB”作为 VLM 输入

3.1 只给视觉原图的问题

仅使用前视 RGB，会让 VLM 依赖单视角图像判断距离、尺寸、队形宽度和无人机动力学约束。对于窄洞、动态门、实体厚度、底部净空等任务，单张图像很难稳定提供可执行策略所需的精确数值。视觉模型可能看出“有一个障碍”，但未必能稳定知道“洞口宽度是否大于单机安全直径”“底部净空是否够无人机下穿”“当前队形是否需要蛇形时序”。

3.2 只给结构化 SFSC 的问题

仅使用 SFSC 虽然几何明确，但会丢失真实视觉形态：例如遮挡、局部开口是否被杂物挡住、悬空障碍底部是否在图像中可见、动态障碍外观是否和传感器估计一致等。对于复杂场景，视觉证据是判断“结构化估计是否可信”的关键。

3.3 最终选择：非视觉结构化约束 + 视觉原图证据

因此最终选择不是把 SFSC 画成图再给 VLM，也不是让 VLM 单独看图，而是同时输入：

  • SFSC：提供距离、尺寸、队形、速度、时序、安全半径、底部净空、顶部目标高度、路线可行性等精确约束。
  • 前视 RGB：提供真实外观、遮挡关系、局部通道形态、视觉异常和 SFSC 一致性证据。

这种设计解决的根本问题是：VLM 擅长语义和形态理解，但不擅长稳定承担数值约束；确定性传感器融合擅长约束表达，但不擅长复杂视觉形态判断。两者互补后，VLM 的任务从“凭图猜控制”变成“在明确物理约束下做高层策略选择”。

3.4 当前输入端进一步强化：路线决策摘要

在复杂实体障碍中，VLM 容易把“垂直通行”误理解成“顶部越障”，或者在明显可下穿时仍选择侧绕。为此当前输入端增加了实体障碍路线决策摘要。该摘要将关键路线变量从大段 SFSC 中提取出来，包括底部净空、是否可下穿、预计下穿高度、所需越顶高度、上下两条路线的 Z 轴代价、推荐垂直路线和确定性兜底策略。

4. 障碍语义抽象与可通行性判断

算法将障碍按功能抽象为两类：穿越型障碍和实体型障碍。穿越型障碍关注孔洞宽度、通过高度和动态中心预测；实体型障碍关注尺寸、厚度、侧绕空间、顶部高度、底部净空和运动状态。

4.1 穿越型障碍

穿越型障碍的基本判断是队形宽度与洞口宽度比较。若完整队形可过，则理论上可保持编队；若完整队形不可过但单机可过，则采用蛇形时序穿越；若单机也不可过，则需要绕行或等待。当前复杂 demo 中，为避免障碍区内“formation”误用，障碍区内不把保持编队作为通行策略，编队恢复仅发生在全体无人机清过障碍区之后。

formation_width = max(y_i) - min(y_i) + 2r_uav
single_file_width = 2r_uav

4.2 实体型障碍

实体障碍不适合用“穿洞”逻辑处理。当前算法把实体通行策略拆成路线族：左侧绕、右侧绕、按队形分流绕、顶部越障、底部下穿，以及在安全范围内由底层按代价自适应选择。实体障碍的策略选择必须满足几何约束：无底部净空不能下穿，顶部目标过高不能越顶，侧绕必须考虑横向安全余量和障碍厚度。

4.3 路线族设计的意义

早期只使用“edge_bypass”会导致 VLM 即使参与，也只能微调 observe_x 和 clear_x，难以体现策略价值。将实体绕障拆分为路线族后，VLM 可以在高层选择“从左侧绕、从右侧绕、越顶、下穿或分流”，底层再根据无人机位置和安全余量生成连续目标。这使 VLM 的贡献从数值微调提升为可观察的策略级改写。

5. 确定性基准策略与 VLM 候选策略

5.1 为什么必须有确定性兜底

VLM 在线推理存在延迟、网络失败、格式错误和理解偏差。多无人机控制不能等待模型返回，也不能让未经验证的模型输出直接改写控制。因此系统先生成确定性基准策略，并立即进入控制缓存。VLM 返回前，底层执行始终连续；VLM 返回后，仅作为候选进入验证和准入流程。

5.2 确定性策略的作用不是替代 VLM

确定性策略提供一个物理可行的下界。VLM 的作用是在这个下界上进行局部策略增强，例如：

  • 将实体障碍从通用边缘绕行改为右侧绕、左侧绕、越顶或下穿；
  • 对动态孔洞延长清障窗口，降低尾机擦碰风险；
  • 在视觉证据显示局部通道异常时提前观察或延后释放；
  • 在 VLM 不确定时确认兜底策略，形成闭环复核证据。

5.3 PassagePlan 作为统一策略接口

VLM 输出必须是可验证的高层策略计划，而不是自然语言建议。计划中包含整体模式、无人机通过顺序、时间槽、每个障碍的局部模式、路线族、观察点和释放点。这样做的原因是：自然语言解释无法直接被控制系统验证；结构化计划可以被检查、比较、投影和缓存。

6. 异步在线重规划与返回时效性门控

6.1 异步机制

在线 VLM 调用通常需要数秒。若控制循环等待模型返回，无人机将失去连续控制。因此当前算法采用异步机制：检测到待规划障碍后，确定性兜底立即进入缓存，同时后台提交 VLM 请求，控制循环继续运行。

6.2 为什么引入 Timeliness Gate

即使 VLM 返回的策略格式正确，也可能已经过期。例如模型基于 7 秒前的图像判断当前障碍，但无人机已经接近或进入执行窗口。此时若强行改写策略，会造成临近障碍突然变道、队列时序破坏或擦碰风险。因此算法加入返回时效性验证。

remaining_x = deadline_x - x_front
TTC = remaining_x / max(v_front, v_min)

只有当剩余距离和 TTC 同时超过阈值，VLM 候选才允许进入安全投影；否则仅作为认知证据记录，不进入底层执行。

6.3 时效性门控解决的根本问题

它解决的是“低频语义模型与高频飞控之间的时间尺度不匹配”。VLM 可以慢，但慢返回的结果不能强行介入近场控制。该机制使大模型参与在线规划，同时不破坏控制安全边界。

7. 安全验证与安全投影

7.1 安全验证

安全验证器检查候选策略的结构完整性、无人机编号合法性、时间槽单调性、障碍覆盖关系、模式与障碍类型匹配、观察点和释放点的几何顺序、实体路线族的可执行性等。特别地，当前阶段已加入对实体路线的几何约束：没有明确底部净空不能下穿，顶部目标过高不能越顶。

7.2 安全投影

通过验证的候选仍会经过安全投影。投影层的目标不是让 VLM 失去作用，而是将 VLM 候选限制在底层稳定执行器能接受的范围内。例如保留全局通过顺序和时间槽、禁止 observe_x 晚于底层策略、禁止 clear_x 短于底层策略、过滤过小窗口噪声、限制清障窗口延长上限等。

7.3 VLM 与确定性安全边界的关系

本算法的学术边界是：VLM 提供候选智能，确定性模块提供安全责任。这样可以避免“模型直接控制无人机”的不可验证风险，同时保留 VLM 对复杂语义和路线族选择的贡献。

8. 底层执行策略

8.1 蛇形时序穿越

对于窄洞类障碍，多无人机采用蛇形时序穿越。核心不是简单排队，而是将每架无人机分配到时空槽，并通过 x 方向速度限制避免后机追上前机。通过顺序可以根据后续障碍和无人机实际位置局部更新，但不会在障碍区内强行恢复完整编队。

8.2 动态孔洞预测对齐

动态孔洞中心随时间变化，因此无人机对齐的不是当前洞口中心，而是预计到达时刻的洞口中心。接近障碍时，横向目标和高度目标逐渐从原队形位置过渡到预测洞口中心与安全通过高度。满足对齐条件后，x 方向快速通过，避免在门体内部反复修正。

8.3 实体障碍执行

实体障碍执行按路线族生成目标。侧绕目标由障碍横向宽度和安全边界确定，越顶目标由障碍顶部高度和垂直安全余量确定，下穿目标由底部净空和无人机半径确定。清障条件考虑实体厚度，避免无人机刚越过中心就过早切换到下一个障碍。

8.4 按无人机个体切换障碍策略

复杂混合场景中，前方无人机可能已经开始处理下一个障碍，而后方无人机仍在处理当前障碍。因此底层不采用“全队统一切换当前障碍”的方式，而是每架无人机根据自身 x 位置、清障状态和当前锁定障碍选择对应策略。这一点显著提高了混合障碍场景下的连续性。

9. 证据链面板与可解释性

证据链面板不是装饰，而是算法可解释性的一部分。它需要回答三个核心问题：原本确定性兜底是什么，VLM 是否起作用，如果起作用具体改变了什么。当前面板围绕“兜底策略、VLM 候选、实际进入底层执行、详细证据链”组织，使观看者不需要阅读日志或源码即可判断 VLM 的真实贡献。

10. 阶段性核心创新点

10.1 SFSC + RGB 的互补式多模态策略输入

创新点不在于简单把图像和文本拼接给 VLM，而在于明确划分两类证据的职责：SFSC 提供可验证数值约束，RGB 提供真实形态证据。该设计避免 VLM 仅凭图像估计几何，也避免结构化上下文丢失视觉异常。

10.2 VLM 作为高层策略候选生成器，而非控制器

算法把 VLM 限定在高层策略层，输出路线族和 PassagePlan 候选，而不是底层速度或姿态指令。这使大模型能力可以进入机器人决策，同时安全责任仍由确定性验证和执行层承担。

10.3 确定性 fallback 与异步 VLM 的控制连续性设计

VLM 延迟不可避免。确定性 fallback 立即进入缓存，异步 VLM 后台计算，避免控制循环等待模型。该机制解决了大模型低频推理与无人机高频控制之间的基本矛盾。

10.4 Timeliness Gate

返回时效性门控是本阶段非常关键的安全机制。它不是简单判断模型是否返回，而是判断返回时是否仍有足够空间和时间执行候选。该机制使“过期但格式正确”的 VLM 策略不会进入控制。

10.5 面向混合障碍的 per-obstacle 策略缓存

策略不再是全局一次性命令，而是按障碍缓存、按无人机位置独立取用。这解决了多无人机在混合障碍中“前机进入下一障碍、后机仍在上一障碍”的异步执行问题。

10.6 实体路线族拆分

将实体绕障从单一 edge_bypass 拆成左绕、右绕、分流、越顶、下穿等路线族，使 VLM 的策略贡献可以体现在“路线选择”而不只是 observe_x / clear_x 微调上。这是复杂 demo 中 VLM 作用可见化的关键。

10.7 路线可行性显式输入与验证

对实体障碍，算法显式计算底部净空、越顶高度、上下路线 Z 轴代价和推荐垂直路线，并在验证器中加入硬约束。该设计解决了 VLM 可能误判“无底部空间也下穿”或“高障碍也越顶”的问题。

11. 当前阶段已经完成的闭环能力

  • 动态窄洞的蛇形时序穿越。
  • 多无人机按时间槽协同通过窄洞。
  • 实体障碍的侧绕、越顶、下穿路线族表达。
  • 有限视野在线感知与异步 VLM 请求。
  • 确定性 fallback 与 VLM 候选并行存在。
  • VLM 候选经过格式验证、几何验证、时效性门控和安全投影。
  • 按障碍缓存的在线策略执行。
  • 可解释面板展示兜底策略、VLM 改写和实际执行结果。

12. 阶段性不足与后续实验建议

当前 demo 已经形成完整算法闭环，但仍有若干研究型问题适合后续实验，而不应继续无边界调参。

  • VLM 对局部视觉形态的稳定性：同一个悬空障碍，模型可能受视角影响选择侧绕而非下穿。后续应通过视角、光照、遮挡和 SFSC 摘要消融分析模型依赖。
  • 路线族消融：分别关闭 VLM、关闭路线族拆分、关闭 Timeliness Gate，比较通过率、碰撞率、平均耗时和策略改写次数。
  • 复杂场景扩展：逐步增加实体障碍种类，而不是一次性堆叠过多障碍。重点观察 VLM 是否产生真实策略级贡献。
  • 实时性实验：比较不同 VLM 模型延迟，分析提前感知距离、飞行速度和 TTC 门槛之间的关系。

14. 阶段性结论

当前算法已经从单纯 demo 调参发展为完整的多模态语义验证时空协同通行框架。其核心不在于“调用了 VLM”，而在于建立了一套可解释、可验证、可异步执行的 VLM 介入机制：VLM 看见视觉证据和 SFSC 约束后提出高层策略；确定性模块保证安全和连续控制；底层执行器按 per-obstacle 缓存实现多无人机混合障碍通行。

从阶段性成果看，该框架已经具备作为论文第一版完整方法的基础：有明确问题定义、分层架构、输入设计逻辑、策略接口、安全验证、时效性门控、在线执行闭环和可解释展示。后续主要工作应转向系统实验、消融分析和论文方法表达，而不是继续无约束修改底层 demo。
